Order Latency Analyzer

Paste gateway logs or add any number of files (.log / .txt / .gz). Two log formats are auto-detected line by line: (1) OMS logs with [NEW_REQUEST] / [EXCH_ORDER_REQUEST] / [EXCH_ORDER_RESPONSE] tags, and (2) gateway logs with [YYYY-MM-DD HH:MM:SS.uuuuuu][INFO][R_IN] / [EX_SND] / [R_OUT] lines, matched on ClOrdID (FIX tag 11). Each file's date is read from a QT_OMS_Logs_YYYY-MM-DD folder name when present, otherwise from the OMS startup line or first log timestamp, so you can pick which dates to analyze. Files are streamed and parsed in a background thread, so the page never freezes. Latencies are computed per QT_OrderID. Everything stays local in your browser.

Skipped orders

Skipped because the step time difference is negative or longer than 5 hours (log clocks / timezones out of sync, e.g. EX_SND logged 5:30 h away from R_IN). They are excluded from every statistic and graph.

Date-wise analysis

One block per log date. If a date has files in different log formats, each format is listed separately (Type 1 = NEW_REQUEST / EXCH_* tags, Type 2 = R_IN / EX_SND / R_OUT). Each row is split by Side (All / Buy / Sell). The side is taken from the NEW request and applied to every MODIFY / CANCEL of the same order (same ClOrdID / QT_OrderID). All values in microseconds.

Log analysis — every measurement

One row per measurement: an order with 5 modifies shows 5 internal + 5 exchange rows. Click a header to sort (click again to reverse); type in the boxes under the headers to filter. Latency accepts >100, <=50 or plain text; times match e.g. 12:10:05. Strategy = the name after the tag, e.g. [NEW_REQUEST]  ManualOrder, (Type 2 logs carry none). Order Side shows Buy / Sell from the original NEW request and is carried across MODIFY / CANCEL measurements.

Latency statistics (microseconds)

P90 / P99 = percentile value. Avg ≤P90 / Avg ≤P99 = mean of the fastest 90% / 99% of samples (tail outliers trimmed). Fast path = internal processing (request → exchange request).
